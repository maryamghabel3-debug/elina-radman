# آوردن ویدیوهای نمونه‌ی سایت — مسیر کار

## چرا من نمی‌توانم دانلود کنم

این محیط sandbox فقط به سه میزبان دسترسی شبکه دارد:

```
github.com        ✅ باز
api.github.com    ✅ باز
pypi.org          ✅ باز
─────────────────────────
alvana.me         ❌ اتصال TLS بسته می‌شود
example.com       ❌ بسته
transfer.sh       ❌ بسته
catbox.moe        ❌ بسته
```

یعنی یک **فهرست سفید** است، نه فیلتر جغرافیایی. هر دامنه‌ای بیرون از این سه، از داخل shell بسته است.
`alvana.me` در DNS حل می‌شود (`84.200.125.137`) و پورت ۴۴۳ هم وصل می‌شود، اما سرور دست‌دادن TLS را نیمه‌کاره رها می‌کند و ۰ بایت برمی‌گرداند.

**نتیجه: تنها راه، GitHub است.** و شما همان را دارید.

---

## کاری که از سمت شما لازم است

### ۱) ویدیوها را در `media/samples/` بگذارید

در رابط وب GitHub، پوشه را باز کنید و فایل را کشیدن-و-رها کنید. یا از خط فرمان:

```bash
git lfs install            # یک‌بار
cd elina-radman
cp /path/to/downloads/*.mp4 media/samples/
git add media/samples/
git commit -m "add sample videos for motion analysis"
git push
```

`.gitattributes` از قبل تنظیم شده: هر ویدیویی در `media/samples/` خودکار با LFS ذخیره می‌شود، پس محدودیت ۱۰۰ مگابایتی GitHub مشکلی نمی‌سازد.

### ۲) خودکار تحلیل می‌شود

با هر push که `media/samples/` را تغییر دهد:

```
.github/workflows/analyze-samples.yml
```

اجرا می‌شود، ffmpeg نصب می‌کند، `scripts/analyze_lessons.py` را می‌راند و گزارش + فریم‌های کلیدی را در **Actions → Artifacts → motion-analysis** می‌گذارد.

می‌توانید دستی هم اجرا کنید: Actions → «تحلیل نمونه‌ویدیوها» → Run workflow.

### ۳) من گزارش را می‌خوانم و ادامه می‌دهم

بعد از اجرا، `analysis/report.md` را ببینم کافی است — همه‌ی اعداد ساختاری همان‌جا هستند و من روی همان‌ها کار می‌کنم.

## چه چیزی برای تحلیل لازم است (و چه چیزی نه)

| نیاز | کافی است | لازم نیست |
|---|---|---|
| تعداد نمونه | **یک** ویدیو از هر سبک | همه‌ی ۲۸ ویدیو |
| طول | **۳۰ تا ۶۰ ثانیه** از هر ویدیو | فایل کامل |
| کیفیت | همان کیفیت اصلی | نسخهٔ 4K |

اگر فایل کامل سنگین است، با ffmpeg خودتان برش بگیرید:

```bash
ffmpeg -ss 00:00:30 -i lesson-04.mp4 -t 60 -c copy lesson-04-sample.mp4
```

## چه چیزی می‌فهمیم — و چه چیزی نه

**می‌فهمیم (خودکار، از روی پیکسل):**

- رندر کد است یا ویدیوی AI — از نسبت پیکسل دقیقاً صفر
- تعداد شات و مدت هر یک
- پالت رنگ و وجود رنگ تاکیدی
- ضخامت خط و یکنواختی‌اش
- سبک زیرنویس (جعبه دارد یا نه، کرااوکه است یا نه، ارتفاع حرف)
- چیدمان (حاشیه‌ها، نوار هدر، نوار زیرنویس)
- ریتم گفتار و طول جمله‌ها

**نمی‌فهمم:**

- **نریشن را رونویسی نمی‌کنم.** من صدا را می‌شنوم نه اینکه به متن تبدیل کنم. اگر متن لازم است، خودتان باید بدهید.
- ابزار دقیق ساخت (Manim یا Remotion یا کد اختصاصی) — شواهد سبک را می‌دهد، نه نام ابزار.
- فایل پروژه‌ی اصلی.

## اگر رضایت‌نامه ندارید

ویدیوهای `stu-*` کار دانشجوهاست. نام فایل هم آن‌ها را لو می‌دهد.
برای تحلیل **ساختاری**، یک نمونه از سبک کافی است — لازم نیست ۲۸ فایل کار دانشجو را آپلود کنید.
